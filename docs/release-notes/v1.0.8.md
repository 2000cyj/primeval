# AgentSpace v1.0.8

这一版把**扩展、Skills、MCP 这三块理顺了** —— 以前它们各自为政，改了这边那边不知道。

---

## 新增

### 内置扩展可以直接改代码

`agentspace.ts`（运行时扩展）以前被编译进命令行二进制 —— 每次落地都重新写一遍，
用户想改都改不了。

现在它有了一份**母本**放在工具箱里：

```text
~/.agent-compose/extensions/builtin/agentspace/index.ts
```

改它，下次落地到项目的就是你改过的版本。母本缺了会自动补一份出厂的，
但**不会覆盖你改过的**。

「编辑」也修好了 —— 以前不管改哪个扩展，一律另存成 `custom/<名字>`，
等于复制一份，改的不是原件。现在**写回它原来所在的地方**。

### 内置扩展并进工具箱

扩展页原来分四组，「内置」单独一组，跟「工具箱」里的 npm / 自定义混在一起。

现在改成三组，工具箱底下再分三个小标题：`npm` / `自定义` / `内置`。

- 内置的**不能删** —— 删了下次启动又补回来
- 但**代码随便改**
- 已选中的停用项也置灰，但**还能取消** —— 不然就再也解绑不了了

### 停用的 Skill / MCP 会置灰

在 Skills 页或 MCP 页把某个东西停了，智能体那边一点提示都没有 ——
还能选、还会被装进项目，agent 照样能用上它。

现在选择弹窗里停用的项**置灰**，标「已停用」，不让新选。

## 变更

- **顶栏的「刷新工具箱」现在刷得全了**。

  以前只重新探测本机装了哪些 CLI，Skills 和 MCP 的列表纹丝不动 ——
  用户按了刷新键，以为全刷了，其实没有。

  现在三个一起刷。而且**页面没开着的时候不会白刷** ——
  KeepAlive 停用的页面 watcher 照样会触发，不盯着的话，
  用户在别的页面按刷新，MCP 这边会在后台白白重连一遍上游。

- **命令行落地时会清掉解绑的 Skill**。

  以前 `agentspace update` 只会往项目里加，不会删。
  解绑了 skill，项目里那份还在，Pi 照样会加载它 ——
  看着像解绑了，其实没解绑。

  现在落地前先删上次落的、这次不绑的，再拷当前绑的。
  用户自己放在 skills 目录里的不动。

  同一个道理，**停用的 skill 也不装了**；之前装过的，这次清掉。

- **远程 Skill 的 Git 来源现在能更新了**。

  `origin.type` 是 `git` 的 skill 提示「没有可更新的来源」——
  更新流程只认 `url` / `local` / `runtime`，漏了 `git` 分支。

  顺带修了个隐蔽的：Git 仓库 fetch 之后**还停在旧提交**上 ——
  现在改成 checkout `FETCH_HEAD`。

- **命令行 `extension list` 多了一列「归属」**。

  区分「这个扩展是 AgentSpace 自带的」还是「用户 / 第三方装的」。
  `--source builtin` 也能只筛内置的。

## 修复

- **筛选器的二级菜单飞出窗口，选项点不到**。

  筛选按钮在工具栏最右边，二级菜单默认往右飞 ——
  实测窗口 1200 宽、面板右边缘在 1150，右边只剩 50px，
  而菜单要 172px，**超出窗口 122px**。

  用户只能看到「使用状态 / 数据来源 / 被谁使用」三个标题，
  真正的选项全在屏幕外。

  现在量一下位置：右边放不下就往左飞，箭头也跟着翻过来。

- **刷新工具箱后版本检查没跟着跑**。

  `latestVersion`（"有新版本"那个徽标）是前端查 npm registry 查出来、
  再写回扫描结果里的 —— 后端返回的对象里根本没这个字段。

  而版本检查原来只在工具箱页面自己跑。一按顶栏刷新，
  扫描换成一批新对象，`latestVersion` 没了，又没人补查 ——
  徽标就消失了。

  现在版本检查挪到共享层，谁触发扫描谁跟着查。

- **扩展页的勾选停用是坏的** —— 直接去掉了。

  core 里 `enabled` 永远是 `true`，停用的文件被扫描时直接跳过。
  所以勾一下，扩展从列表里消失，**你再也找不到它**，也没法勾回来。

  命令行的 `extension enable/disable` 保留 —— 那是另一套路径。

- **扩展来源分不清「用户级 / 项目级 / 工具箱」**。

  以前全混在一起，而且 pi 自动发现的扩展显示成「Pi 自带」——
  但 Pi 自带的和 AgentSpace 自带的完全是两回事。

  现在顶层分「用户级 / 项目级 / 工具箱」，各自归位。

- **内置扩展的母本可能被出厂内容覆盖** —— 不会了，只补不覆盖。

- **解绑的 skill 落地后还赖在项目里** —— 见上面「变更」。

## 已知限制

- **便携版（zip 解压即用）不支持应用内更新** —— 它不是安装版，没有可替换的
  安装目录。安装版（`AgentSpace_*_x64-setup.exe`）不受影响。

- **远程 skill 和 npm 扩展导入时要联网** —— 它们按来源重新拉 / 重装。

- **自动备份只在应用开着的时候做** —— 关着的时候没有进程，也就没有定时器。
  下次启动时会补一次：只按「最新备份比间隔旧不旧」判断，所以关了三天再开，
  **只补一份**最新快照，不会补一堆。

- **备份的是配置数据，不是程序本体** —— 恢复回来的是智能体、Skills、
  MCP server、Pi 扩展和 Wiki 页面。

- 导出的 OAuth 令牌、`tools.json` 缓存、agent 运行历史**不导出** ——
  敏感或没有意义。`${ENV:NAME}` 这类占位原样保留，导入方自己配环境变量。
