# AgentSpace v1.0.5

这一版的主线是**内置知识库** —— AgentSpace 里长出一个 Wiki，智能体可以拿它当知识库用。

顺带把命令行的能力补齐了（桌面端能做的，命令行现在都能做），以及修了一个
`agentspace run` 起来后界面一片空白、看着像卡死的毛病。

---

## 新增

### 内置 Wiki：知识库就在应用里

侧边栏多了一项 **Wiki**（在 MCP 下面）。

- 左边是**页面树**，按父子关系分组；新建页面可以指定父页面
- 正文用 **Markdown 编辑**，右边实时预览
- **搜索**在正文里全文找，命中给出所在行和片段
- **标签**用来筛选和找相关页面
- 一页可以**发布成 Skill** —— 同一份内容，别的智能体也能用

Wiki 页面存在 `~/.agent-compose/wiki/<slug>/`（正文是 `page.md`，元信息在
`.meta.json`），是本机存储，不依赖任何外部 Wiki 服务。

### Wiki 成为智能体的知识库

给智能体绑一个 **Wiki 入口页面**，它连同子树就成了这个智能体的知识库。

绑定的是**入口页**，不是一堆具体页面 —— 以后在入口下面加子页，智能体那边
不用改配置，自动继承。

注入分**两层**，这是刻意的：

- **指令里只放标题、slug、标签** —— 让智能体知道「有什么」
- **正文要它自己去拉** —— 让它自己决定「看哪一篇」

全部正文一次性灌进 prompt 会把上下文吃光，而且智能体根本不知道该看哪一篇。
这跟 skill 的处理是同一个哲学：只告诉它有什么，内容它自己拿。

配套给了三个工具：`wiki_search`（检索）、`wiki_read`（读全文）、
`wiki_neighbors`（顺着知识图谱看关联页面）。页面之间用 `[[slug]]` 互相引用，
这些引用就是知识图谱的边。

### 命令行把业务操作补齐了

以前桌面端能做的，命令行做不了。现在两边操作的是同一份数据，
**桌面端的每个业务操作，命令行都有一份**。

新增的命令组：

- `agentspace wiki ...` —— 知识库全量操作（list / get / create / update /
  delete / search / tags / neighbors / publish）
- `agentspace backup ...` —— 数据管理的导入导出（inventory / export / inspect / import）
- `agentspace app update` —— 查桌面端有没有新版本
- `agentspace mcp profiles|authorize|registry|open-url` —— 配置档、OAuth 授权、
  官方目录搜索、开浏览器
- `agentspace agent wiki ...` —— 智能体绑 Wiki 入口页面

还有一条 `agentspace version`，一条看完所有版本号（AgentSpace 自己，加上工具箱里
各个 CLI 工具的版本）：

```console
$ agentspace version --check
AgentSpace
  桌面端    1.0.5
  命令行    1.0.5

工具箱
工具                本机版本  registry
Claude Code         2.1.322   最新 2.1.326（有新版）
Codex               0.162.1   最新 0.169.0（有新版）
Pi                  1.5.2
...
```

`version` / `-version` / `-v` 三种写法都认。

### 帮助中心加了「版本」页签

右上角帮助中心原来只有「命令行」和「页面」两块，现在多了第三块 **版本**：

- 当前版本
- 「检查最新版本」
- 有新版时显示版本号、发布日期、发布说明，直接「更新到 X.Y.Z」
- 下载进度条 —— 下载、验签、装完重启全在应用内完成，不跳浏览器

另外补齐了两块内容：**界面说明**里原先没有 Wiki 这一页，系统设置也漏了
「命令行安装状态」「数据管理」「出站代理」三个板块。

### Skill 编辑器改成独立视图

手动创建 skill 原来是「小弹窗填名字 + 大页面写正文」，写长文要在两个地方来回切。
现在**编辑器是独立的一页**，带返回按钮，离开时会明确提示有没有没保存的修改。

## 变更

- **侧边栏的 Wiki 挪到了 MCP 下面** —— 两者都是「给智能体提供能力」的入口，
  挨着放。

- **时间显示统一成 `YYYY-MM-DD HH:mm:ss`**（本地时间）。以前有的地方显示到秒、
  有的地方只到分，还有的不带年份。现在凡是显示年月日时分秒的地方，一律本地时间、
  一秒不落。

- **「有新版本」用红色**。版本列里那个提示原来是中性色，跟普通信息看不出差别。

- **帮助中心的分组调整了**：「桌面端自身」并进了「agentspace 自身」—— 起智能体
  和查版本都是这条命令自己该干的事，拆成两组反而让人以为是两套东西。

- **数据管理也能带上 Wiki 页面了** —— 导出时勾上，导入时一起带走。

- **README 的功能表补全了** —— 加上了 Wiki 和数据管理。

## 修复

- **`agentspace run` 起来后界面一片空白，看着像卡死**。

  根因是起 Pi 的命令带了个 `CREATE_NO_WINDOW` 标志 —— 那个标志的语义是
  「不给这个进程设置控制台句柄」。Pi 是交互式 TUI，靠控制台 API 进 raw mode、
  查光标位置、画界面，拿不到控制台就一个字都画不出来。终端里只剩准备阶段打的
  那两行，看起来就像卡住了。

- **帮助中心的版本号显示 1.0.0**（实际装的是 1.0.4）。那是个写死的兜底值：
  原实现问后端要版本号，要不到就用兜底值顶上 —— 而写死的数字不会跟着发版更新。
  现在版本号从 `tauri.conf.json` 编译进去，同时也问后端要一份，两边都不会显示错。

- **补 skill 的 description 时少一个换行**，frontmatter 直接解析失败，
  skill 的说明整个读不出来。

- **frontmatter 坏了的文件会「雪球」** —— 每存一次就把坏的那段也一起存进去，
  越存越坏。现在保存时重建干净的 frontmatter。

- **Wiki 工具出错时没标记成失败**，智能体以为调用成功了。

- **数据管理**：只带 Wiki 页面的导出包会被说成「空包」；导入时也看不到 Wiki
  页面的冲突清单（界面上那个「覆盖」勾选因此是死的）。

## 已知限制

- **便携版（zip 解压即用）不支持应用内更新** —— 它不是安装版，没有可替换的
  安装目录。安装版（`AgentSpace_*_x64-setup.exe`）不受影响。

- 导出的 OAuth 令牌、`tools.json` 缓存、agent 运行历史**不导出** ——
  敏感或没有意义。`${ENV:NAME}` 这类占位原样保留，导入方自己配环境变量。

- **命令行里的 `app update` 只能查版本，装不了** —— 下载、验签、装完重启是
  桌面端的事（走 Tauri 官方 updater），命令行只报「有没有新版」。

- **Wiki 是本机的** —— 页面存在 `~/.agent-compose/wiki/`，不进导出包以外的
  任何地方，也不跟外部 Wiki 服务同步。
