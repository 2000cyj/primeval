# AgentSpace v1.0.7

这一版把**数据管理的导出/导入补完整了** —— 以前导出的包，导入到另一台机器上
会少东西。现在一个智能体绑的东西，导过去能原样用起来。

另外顶栏多了一个**刷新工具箱**按钮：一键重新探测本机装了哪些 CLI，
侧边栏的计数和工具箱页面同步更新。

---

## 新增

### 顶栏的「刷新工具箱」

帮助按钮旁边多了一个刷新图标，点一下就重新探测本机装了哪些 CLI。

放在那儿是因为它和帮助按钮是同一类操作 —— **全局的，不属于当前页面**。
不管你正停在哪个页面，点它都刷的是同一份数据。

- 扫描中图标转圈
- 成功弹一句「工具箱已刷新」
- 失败说清楚原因（比如「sidecar 未运行」），并把旧数据清掉 ——
  留着上次的结果会让人以为「现在还是这样」，其实是过期的

### 远程 skill 的导入不再丢

以前导出包里的远程 skill 只记了「来自哪个仓库」，导入时靠猜路径，
只试 `skills/<名>/SKILL.md` 和 `<名>/SKILL.md` 两种。

问题是**仓库布局根本不统一**：

| 布局                  | 例子                                              | 以前能导回来吗 |
| --------------------- | ------------------------------------------------- | -------------- |
| `skills/<名>/`        | `using-agent-skills`                              | ✅             |
| `skills/<组>/<名>/`   | `mattpocock/skills` 的 `skills/engineering/<名>/` | ❌             |
| 仓库根就是 `SKILL.md` | `remote-develop-skills`（路由型的 skill）         | ❌             |

一个绑了 48 个 skill 的智能体，**有 8 个在别的机器上导不回来**。

现在导出时会把 skill 在仓库里的**真实相对路径**一起记下来，导入时照着找。
记不下来也没关系 —— 导入端还有兜底：候选路径都不中就按名字在仓库里找。

顺手修掉一个隐患：有些仓库里**同一个 skill 有多份副本** ——
`ponytail` 仓库里既有 `skills/ponytail/SKILL.md`，也有
`.openclaw/skills/ponytail/SKILL.md`（给别的工具链准备的适配版），
两份内容可能不一样。所以查找顺序是「先试明确路径，再按名字找」，
不会挑错。

### Wiki 子树跟着一起导出

智能体绑的是 Wiki 的**入口页面**，它的整棵子树自动跟着可见。
那导出时也得把子树带上 —— 以前只带走入口页，子页面留在家里了。

### 一个现成的智能体预设包

`presets/fullstack-engineer.zip` —— 装出来就是「全栈开发工程师」
（Java 8 / Spring Boot 2.7 后端 + Vue 3 前端），含 48 个 skill、
3 个 MCP server、5 个 Pi 扩展。

用的是「数据管理」那套格式，所以导入方式跟普通备份包一样：
`agentspace backup import`，或者桌面端的**系统设置 › 数据管理 › 导入数据**。

## 变更

- **工具箱的探测结果改成模块级共享**。

  以前工具箱页面自己存一份探测结果，侧边栏的计数读的是另一份。
  现在侧边栏的计数、工具箱页面的列表、顶栏的刷新按钮看的都是**同一份** ——
  顶栏刷完，切到工具箱页面看到的就是新的，不用重新加载。

- **命令行 `backup export --agent` 现在认名字也认 id**。

  以前只认 id。传了名字会**静默地导不出任何智能体** —— 导出结果里显示
  「0 个智能体」，看着像包是好的，其实少了一半。

- **探测进行中改用计数器** —— 可能有多个扫描同时在跑（顶栏刷新的同时
  页面在加载），先结束的那个不该把另一个的转圈关掉。

---

## 修复

- **远程 skill 查找漏掉仓库根目录的 `SKILL.md`**。

  找 skill 的函数只往下递归，不看根目录自己 —— 而路由型的 skill 恰恰
  就在仓库根上（`remote-develop-skills` 就是）。

- **按名字找 skill 可能挑到「适配版」** —— 见上面「顺手修掉一个隐患」。

- **探测失败时留着旧数据** —— 现在清掉，跟「不展示假数据」的约定一致。

---

## 已知限制

- **便携版（zip 解压即用）不支持应用内更新** —— 它不是安装版，没有可替换的
  安装目录。安装版（`AgentSpace_*_x64-setup.exe`）不受影响。

- **远程 skill 和 npm 扩展导入时要联网** —— 它们按来源重新拉 / 重装。

- **自动备份只在应用开着的时候做** —— 关着的时候没有进程，也就没有定时器。
  下次启动时会补一次：只按「最新备份比间隔旧不旧」判断，所以关了三天再开，
  **只补一份**最新快照，不会补一堆。

- **备份的是配置数据，不是程序本体** —— 恢复回来的是智能体、Skills、
  MCP server、Pi 扩展和 Wiki 页面。

- 导出的 OAuth 令牌、`tools.json` 缓存、agent 运行历史**不导出** ——
  敏感或没有意义。`${ENV:NAME}` 这类占位原样保留，导入方自己配环境变量。
