# 数据管理 —— 导入 / 导出本地配置

## 目标

在「系统设置」里加一个「数据管理」卡片，能把本机的智能体、Skills、MCP server、Pi 扩展
导出成一个包，也能在另一台机器上导回来。

参考 cc-switch 的「数据管理」（导入导出配置），但导出粒度更细：
**远程来源的导出下载链接，本地手写的导出原文件。**

## 场景

1. 换机器 → 导出 → 拷贝过去 → 导入 → 配置齐活
2. 备份 → 手滑删了一个 skill → 从备份导回来
3. 把一套私有 MCP server / 自定义扩展分享给同事

## 导出

### 选什么

弹窗里勾选：

- **智能体**（多选）
- **Skills**（多选）
- **MCP server**（多选）
- **Pi 扩展**（多选）

勾了智能体 → 自动把它引用的 skills / mcp servers / extensions 也带上（智能体本身存的是
路径引用，不带上的话导入后是空壳）。已经在手动勾选里的不重复。

### 导出成什么

ZIP：

```
AgentSpace-export-20261114-163000.zip
  manifest.json              清单
  skills/<目录名>/...        本地 skill 的原文件
  mcp/servers.json           手动配置的 MCP server 定义
  extensions/<目录名>/...    自定义扩展的原文件
  agents/<id>/agent.json     智能体定义
  agents/<id>/AGENTS.md      智能体说明
```

`manifest.json`：

```json
{
  "version": 1,
  "app": "AgentSpace",
  "exportedAt": "2026-11-14T08:30:00Z",
  "agents": [
    {
      "id": "agent-xxx",
      "name": "agent-java8-vue3",
      "files": ["agents/agent-xxx/agent.json", "agents/agent-xxx/AGENTS.md"]
    }
  ],
  "skills": [
    {
      "name": "vue",
      "kind": "remote",
      "origin": { "type": "git", "sourceUrl": "github.com/…", "sourceRef": "0.6.13" }
    },
    { "name": "my-skill", "kind": "local", "files": ["skills/my-skill/SKILL.md"] }
  ],
  "mcpServers": [
    { "id": "idea", "name": "idea", "kind": "remote", "registryName": "io.github.jetbrains/idea" },
    { "id": "my-db", "name": "my-db", "kind": "local", "file": "mcp/servers.json" }
  ],
  "extensions": [
    { "name": "context-mode", "kind": "remote", "package": "@mksglu/context-mode" },
    { "name": "my-ext", "kind": "local", "files": ["extensions/my-ext/index.ts"] }
  ]
}
```

### 远程 vs 本地怎么判

| 类型    | 远程（只记链接）                                                      | 本地（打包原文件）                            |
| ------- | --------------------------------------------------------------------- | --------------------------------------------- |
| Skill   | sidecar `origin.type` 是 `git` / `url` → 记 `sourceUrl` + `sourceRef` | `manual` / `local` / `runtime` → 打包整个目录 |
| MCP     | 从 registry 装的 → 记 registry 名                                     | 手动填的 → 记 def JSON                        |
| Pi 扩展 | `source = npm` → 记 npm 包名                                          | `source = custom` → 打包文件                  |

> MCP 要能判出「从 registry 装的」，得在 `servers.json` 的条目里记一下来源。
> 现在没记 —— 这次加上（`registryName` 字段，缺省视为手动配置，不影响老数据）。
>
> 扩展以**目录**为单位导（不是扩展文件）—— 一个 npm 包声明了三个扩展文件，
> 按文件列会出现三遍同名。npm 目录名是扁平的（`@dietrichgebert-ponytail`），
> 显示时用 package.json 里的原包名。

### 远程的东西怎么导回来

| 类型            | 怎么重建                                                      |
| --------------- | ------------------------------------------------------------- |
| Skill（git 源） | 按 `sourceUrl` + `sourceRef` 重新 clone，从仓库里找同名 skill |
| MCP（registry） | 调官方目录的 `/v0/servers/{name}/versions/latest` 取回定义    |
| Pi 扩展（npm）  | `npm install <包名>`                                          |

## 导入

### 流程

1. 选 zip → 解析 manifest
2. **冲突检查**：逐条比对本地已有的数据，同名的算冲突
3. 弹窗列出冲突项，每条一个「覆盖」复选框，**默认全不勾**（= 跳过这条）
4. 确认后逐条处理：
   - 远程 → 下载（skill 走 git / npm 扩展走 npm install / MCP 走 registry 查找）
   - 本地 → 写入本地目录（skill 解压到 skills 仓库 / MCP 合并进 servers.json / 扩展写进 extensions/custom）

### 冲突规则

| 情况                    | 处理                             |
| ----------------------- | -------------------------------- |
| 同名 skill 已存在       | 勾了覆盖 → 替换目录；没勾 → 跳过 |
| 同 id MCP server 已存在 | 勾了覆盖 → 替换定义；没勾 → 跳过 |
| 同名扩展已存在          | 勾了覆盖 → 替换目录；没勾 → 跳过 |
| 同 id 智能体已存在      | 勾了覆盖 → 替换定义；没勾 → 跳过 |

默认不勾 = 导入是**增量**的，不会毁掉本机已有的东西。

### 冲突列表的分组

跟导出弹窗的分组一致：**智能体 / Skills / MCP server / Pi 扩展**。

每组一个「全选覆盖」勾选框（勾了一部分时是半选状态）——
一个包几十条冲突时，一条条勾太累。

## 导入是异步的

导入可能要拉远程仓库（远程 skill 重新 clone）、跑 `npm install`（远程扩展）——
几十秒起步。同步做界面会卡住，用户以为死了。

所以 `backup_import` 立刻返回 `taskId`，导入在后台线程跑：

| 事件                     | 负载                                         | 什么时候    |
| ------------------------ | -------------------------------------------- | ----------- |
| `backup-import-progress` | `{ taskId, phase, current, total, message }` | 每处理一条  |
| `backup-import-done`     | `{ taskId, result }` 或 `{ taskId, error }`  | 跑完 / 失败 |

**进度写到顶栏的通知里**（铃铛）—— 用户可以关掉弹窗去干别的，
导入照样跑完，跑完了铃铛里能看到结果。

core 层用进度回调（`Option<&dyn Fn(ImportProgress)>`）—— CLI 也能用同一套
（打一行就行），不用把事件机制带进 core。

## 界面

「系统设置」页面加一张卡片：

```
数据管理  ⓘ
导入和导出本地配置数据

[导出数据]  [导入数据]
```

- **导出数据** → 勾选弹窗（智能体 / Skills / MCP server / 扩展 四组多选）→ 选保存位置 → 生成 zip
- **导入数据** → 选 zip → 冲突弹窗（按类型分组 + 覆盖勾选框）→ 确认 → 后台跑 → 顶栏通知报进度

## 边界

- 导出的 OAuth 令牌、`tools.json` 缓存、agent 运行历史**不导出** —— 敏感或无意义
- 敏感值（`${ENV:NAME}` 占位）原样保留，导入方自己配环境变量
- 智能体里引用了但没被导出的 skill → 导入后引用悬空，界面提示「有 N 个引用没找到」

## 不做

- 不做跨设备同步（不做在线账号）
- 不做导出到云盘（用户自己拷文件）
- 不做导出时加密
